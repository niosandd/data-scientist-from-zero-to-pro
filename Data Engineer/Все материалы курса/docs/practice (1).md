# Практическая работа – Проектирование DWH для оценки бизнес-эффективности

## Цель
Цель этого задания — попрактиковаться в проектировании Data Warehouse (DWH), который поможет оценивать и улучшать эффективность бизнеса, например, отслеживать продажи или анализировать такие метрики, как заполняемость самолётов. Как бонусное задание, нужно будет создать витрину данных (Data Mart) для анализа активности продаж, например, по ежедневным продажам билетов.

## Что нужно сделать:
1. **Выбрать бизнес-домен** (например, авиаперевозки, телеком).
2. **Спроектировать структуру DWH** для выбранного домена, который будет хранить такие данные, как продажи и использование услуг.
3. **Создать ER-диаграмму** исходных данных с помощью любого инструмента (Excel, Draw.io и т.д.).
4. **Спроктировать модель Data Vault**, включающую Hub, Satellite, Link таблицы.
5. **Создать звездообразную схему** для витрины данных (опционально).



### Окружение:
- Используйте любую доступную SQL-базу данных или инструменты для визуализации.


## Этапы выполнения работы:

### Этап 1: Анализ и выбор исходных данных
- **Задача**: Определитесь с бизнес-доменом и типом данных (например, ежедневные продажи или заполняемость рейсов).
- **Например**: Цифровые двойники - https://github.com/PawaritL/databricks-azure-digital-twin/tree/main/models.
- **Например**: Поддержка клиентов - https://github.com/databricks-industry-solutions/Email-Customer-Support/tree/main/data.
- **Например**: Telecom - https://notebooks.databricks.com/notebooks/CME/telco-reliability/index.html#telco-reliability_1.html.
- **Действия**: 
  - Если диаграммы данных нет, создайте ER-диаграмму с помощью инструмента на выбор.
  - Выберите ключевые бизнес-метрики для анализа, например, общие продажи или заполняемость самолётов.

### Этап 2: Проектирование модели Data Vault
- **Задача**: Разработать модель Data Vault, которая будет включать таблицы Hub, Satellite, Link.
- **Действия**:
  - **Hub**: Содержит уникальные бизнес-ключи (например, Flight ID, Ticket ID).
  - **Satellite**: Содержит описательные данные (например, детали рейсов, информация о продажах).
  - **Link**: Соединяет Hub таблицы (например, связь между рейсами и продажами).

### Этап 3: Связи между исходной и целевой диаграммами
- **Задача**: Нарисовать связи между исходной ER-диаграммой и целевой моделью Data Vault.
- **Действия**:
  - Создайте финальную диаграмму, показывающую, как исходные данные транслируются в Data Vault.

### Этап 4 (опционально): Создание витрины данных для анализа продаж
- **Задача**: Спроектировать витрину данных на основе звездообразной схемы для анализа продаж (опциональное задание).
- **Действия**:
  - Fact Table: Хранит данные о продажах (например, продажи билетов по дням).
  - Dimension Tables: Хранят описательные данные (например, данные о рейсах, информация о клиентах).

2. **Проектирование Data Vault**:
   - Убедитесь, что модель Data Vault включает хотя бы один Hub, Satellite и Link.
   - Проверьте связи между исходной моделью и созданным Data Vault.

3. **Опциональная витрина данных**:
   - Если бонусное задание выполнено, проверьте, что звездообразная схема корректна.
   - Убедитесь, что в Fact таблице хранится правильная бизнес-метрика (например, продажи или заполняемость самолётов).

## Детальная проверка:

### Этап 1: Анализ исходных данных
- **Проверка**:
   - Убедитесь, что участник выбрал чёткий бизнес-домен.
   - Проверьте, что ER-диаграмма (если она есть) правильно отображает сущности и их взаимосвязи.

### Этап 2: Проектирование модели Data Vault
- **Проверка**:
   - Hubs: Проверьте, что Hub таблицы содержат уникальные ключи бизнес-сущностей (например, Flight ID).
   - Satellites: Убедитесь, что Satellite таблицы содержат описательную информацию (например, расписание рейсов, количество мест).
   - Links: Проверьте, что Link таблицы корректно связывают Hubs (например, связывают продажи билетов с деталями рейсов).

### Этап 3: Соединение исходных и целевых диаграмм
- **Проверка**:
   - Финальная диаграмма должна чётко показывать связи между ER-диаграммой и таблицами Data Vault.
   - Связи должны быть логичными, ключи должны быть согласованы между моделями.

### Этап 4 (опционально): Создание витрины данных
- **Проверка**:
   - Звездообразная схема должна содержать Fact таблицу с бизнес-метриками (например, продажи билетов по дням).
   - Dimension таблицы должны содержать релевантные описательные данные (например, номера рейсов, демография клиентов).

Эти рекомендации помогут убедиться, что участник успешно понял ключевые концепции проектирования DWH и анализа бизнес-данных.
